# --- AI segmentation, ToothGroupNetwork (required by POST .../segment) ---
# All four are on the live inference path, verified by import, not assumed:
#   inference_pipelines/inference_pipeline_tgn.py imports gen_utils and open3d,
#   and gen_utils imports trimesh; sklearn is used across gen_utils, ops_utils
#   and the pipeline itself.
# Omitting any one of them means /segment returns "AI segmentation unavailable"
# while the rest of the clinical loop still works — tgn_bridge is built so a
# missing model can never take the server down.
#
# CPU-only by design: cpu_compat.py and pointops_cpu.py shim away the CUDA
# assumptions in the vendored network. The default PyPI torch wheel is CPU;
# only add the PyTorch CUDA index if you deliberately want GPU.
torch

trimesh
open3d

# --- AI segmentation, CrossTooth (the second provider, ?provider=crosstooth) ---
# einops is the ONLY package CrossTooth adds, and it is genuinely load-bearing:
# `models/PTv1/point_transformer_seg.py` uses einops.reduce and einops.rearrange
# inside PointTransformerLayer.forward, and that file is vendored third-party
# code this project does not edit. It is pure Python with no dependencies.
#
# THREE THINGS CrossTooth's OWN requirements.txt ASKS FOR AND DOES NOT GET HERE,
# each for a reason rather than an oversight:
#   pointops  - a CUDA extension. It does not build on Windows without a
#               toolchain, AND the import path the vendored model uses
#               (models.PointTransformer.libs.pointops.functions) does not
#               exist in the shipped repository on any platform. crosstooth_
#               bridge.py registers that name against this project's existing
#               pointops_cpu.py shim instead.
#   vedo      - only `dataset/data.py` uses it, to load a mesh from disk. This
#               app already holds vertices and faces, and the feature
#               preparation is replicated in crosstooth_bridge.CrossToothAdapter
#               .prepare. Installing a VTK stack to re-read a mesh we have in
#               memory would be a 100MB dependency for nothing.
#   spconv / flash-attn / torch-scatter / torch-sparse / torch-cluster /
#   torch-points3d / pykeops
#             - none is imported by the PTv1 inference path. They belong to the
#               training code and to the 12 competing methods in `compete/`.
#               Verified by following the import chain, not by reading the
#               requirements file (CLAUDE.md s.19 records getting that wrong
#               the other way round for trimesh and open3d).
einops

# --- Encrypted local case files (opt-in treatment-state persistence) ---
# Never hand-rolled: Fernet gives AES-128-CBC plus an HMAC-SHA256 tag, so a
# tampered or truncated case file is REJECTED rather than silently decrypted
# into a half-plan. Treatment state only - no scan geometry is ever written.
cryptography
